# ФП‑Контроль

Локальный портал для мониторинга и планирования обязательств по статьям ФП (финансового плана) за квартал. Загружаете Excel-подложку, систему распределяете обязательства по ответственным, отслеживаете сроки и риски на дашборде.

## Что внутри

- **Спросить портал** — вверху дашборда квартала. Локальный поиск (без ИИ, без интернета и ключей API) по клиентам, разделам, рискам и обязательствам: название клиента («Сбербанк»), раздел/портфель («возможности по TaaS», «факт по сопровождению»), ключевые слова «риски», «обязательства», «просрочки», «горящие сроки» — и сразу получаете сводку в моноширенном блоке (итоговые суммы + таблица). Работает мгновенно, отдельной настройки не требует — см. раздел «Умный поиск по порталу» ниже про то, какие запросы он понимает.
- **Дашборд периода** — Факт показан отдельным блоком, рядом — кубик «Факт + План 0‑100» (сумма уже полученных денег и того, что должно прийти по плану, по всем разделам). Дальше — фокус-блок «План 0‑100 / Возможности» по разделам Проекты, Заказные доработки, Лицензии, **Сопровождение и TaaS** (весь основной упор работы, включая разделы только для отслеживания — иначе их прогресс по плану/возможностям было неудобно отслеживать). Дальше — целевая сумма периода с % выполнения и тремя метриками разрыва (сколько остаётся добрать после Факта; после Факта+План 0‑100; после Факта+0‑100+Возможности) — считается по всем разделам без исключений. Разбивка по разделам ФП, выпадающие фильтры по клиенту и ответственному (влияют на списки просрочек/рисков, не на саму цель), просрочки, горящие сроки (≤3 дня). Дальше — блок **«Статьи без оформленного обязательства/ответственного»**: проектные и закупочные статьи без назначенного руководителя/Owner, с кнопками быстрого действия прямо в строке — «+ Ответственный» (минимальная форма, только выбор ответственного) и «+ Обязательство» (текст, ответственный, срок) — обе сразу возвращают на дашборд после сохранения. Чтобы не перегружать список несущественными суммами, показаны только статьи с суммой 0‑100 от 300 000 ₽. Отдельный блок в самом низу — «Сопровождение и TaaS» по клиентам (Факт/0‑100/Возможности), только для отслеживания, без требования об ответственном и без участия в рисках; суммы Факт, 0‑100 и Возможности — ссылки на детализацию по этому клиенту и разделу. Период определяется по месяцам, реально присутствующим в загруженном файле; месяцы, выпадающие из основного календарного квартала, подсвечиваются отдельно. Все ключевые суммы (Факт, Факт+План 0‑100, План 0‑100, Возможности, «достигнуто», итоги и строки в «Разбивке по разделам ФП») — ссылки, открывающие «Детализацию» с готовым фильтром по разделу/портфелю на эти же суммы.
- **Детализация** (бывшая «Статьи ФП») — выпадающие фильтры (раздел, портфель, клиент, менеджер, текстовый поиск) и переключатель **«Детально» / «Агрегировано по клиентам»**.
  - *Агрегировано по клиентам* — открывается по умолчанию. Плоская таблица: Клиент, Категория (Проекты / Заказные доработки / Докупки — Лицензии объединены с Докупками), Менеджер(ы), 0‑100, Возможности, Итого, Факт, Комментарий, Обязательства, Риск. Колонка «Комментарий» собирает в одну ячейку все комментарии из вошедших в группу строк детализации. Колонка «Обязательства» — кнопка-ссылка на детализацию, если хотя бы по одной строке группы есть оформленное обязательство, иначе — неактивная кнопка «Нет». Колонка «Риск» показывает бейдж максимального уровня риска в группе (см. ниже). Колонка «Факт» (бледно-зелёная заливка) — справочная сумма по портфелю «Факт» для этих же клиента/категории, в расчёт «Итого» не входит; клик по сумме открывает детализацию, отфильтрованную по Факту. Клиенты с нулевым Итого по категории не выводятся вовсе, **кроме** случаев, когда по ним есть ненулевой Факт — такие группы всё равно показываются (иначе реальные деньги были бы не видны), но принудительно опускаются в самый низ таблицы (независимо от выбранной сортировки) и выделяются зелёным целиком с пометкой «только факт». Любой столбец кликабелен для сортировки, по умолчанию — по убыванию Итого. Строки таблицы чередуются по цвету, чтобы не сливаться друг с другом. Сопровождение и TaaS сюда не входят (смотрите дашборд квартала). Суммы — ссылки: клик по 0‑100/Возможности/Итого/Факт открывает «Детально» с готовым фильтром по этому клиенту, разделу и портфелю.
  - *Детально* — таблица всех строк за период с сортировкой по любому столбцу (клик по заголовку, включая «Менеджер»), группировкой и подытогами по каждой группе и в целом. Порядок столбцов: Клиент, Договор, Номер проекта, Проект, Раздел, Менеджер, ДПА, Сумма 0‑100, Портфель. Обязательства разворачиваются прямо в строке таблицы по клику. Там же — выпадающий список «Риск» (только у Owner) с тремя уровнями: Низкий риск (жёлтый, ~90% вероятность получить деньги), Средний риск (оранжевый, ~70%), Высокий риск (красный, ~50%). Отмеченная строка подсвечивается соответствующим цветом и отражается бейджем в столбце «Риск» агрегированной таблицы (берётся максимальный уровень среди строк группы). Ответственного в уже созданном обязательстве можно сменить выпадающим списком — это право есть только у Owner.
- **Кнопка «← Назад»** — на внутренних страницах (Детализация, Мои обязательства, Изменения, Загрузка Excel, Пользователи) есть кнопка быстрого возврата на предыдущую страницу.
- **Мои обязательства** — личный список для каждого руководителя команды.
- **Загрузка Excel** — повторная загрузка подложки без потери уже созданных обязательств, с подробной сводкой изменений (что нового, что изменилось — с указанием старого и нового значения, что пропало) сразу после загрузки и в истории.
- **Изменения** (только Owner) — постоянная очередь на просмотр, которая копится между загрузками (а не сбрасывается после следующей). Три вкладки: «Новые статьи» (новые + вернувшиеся в файл строки), «Закрытые / обнулённые» (сумма 0‑100 упала до нуля, либо строка вообще пропала из файла — обе ситуации означают, что деньги выпали из плана), «Прочие изменения» (изменение суммы без обнуления, смена менеджера, ДПА/СДЗ/фДЗ, портфеля). Фильтр «Дата загрузки» сужает список до событий конкретной загрузки Excel (по умолчанию — «Все загрузки»), фильтр сохраняется при переключении вкладок и при пометке «просмотрено». Каждую строку можно отметить «просмотрено» (или все сразу — в пределах текущего фильтра по дате), бейдж с количеством непросмотренных виден в меню и на дашборде квартала.
- **Пользователи** — управление логинами и ролями (только для Owner), генерация кодов привязки Telegram.
- **Telegram-бот** — отдельный процесс, через который можно добавлять обязательства, менять их статусы кнопками, получать напоминания о просрочках и горящих сроках, и запрашивать актуальную информацию по клиенту прямо в Telegram. Любой вопрос без команды отвечает тот же ИИ-чат, что и «Спросить портал» на дашборде. Запускается вместе с порталом и автостартует с компьютером (см. «Автозапуск» ниже).

## Telegram-бот

Бот работает как отдельный процесс рядом с порталом (использует ту же базу `app/data/fp_portal.db`) и не требует никаких облачных сервисов — только бесплатный Telegram Bot API.

### Настройка (один раз)

1. В Telegram напишите боту **@BotFather**, отправьте `/newbot`, придумайте имя — в ответ вы получите токен вида `123456789:AAAA...`.
2. Создайте файл `bot/token.txt` в папке проекта и вставьте туда токен (одна строка, без пробелов). Либо задайте переменную окружения `FP_BOT_TOKEN` перед запуском.
3. Запустите бота:
   ```
   python3 run_bot.py
   ```
   В терминале появится `[bot] Авторизован как @ваш_бот`. Оставьте это окно терминала открытым — бот работает, пока запущен процесс (как и сам портал).

### Прокси (если api.telegram.org заблокирован без VPN)

Бот обращается к Telegram Bot API по обычному HTTPS, напрямую — в РФ это часто доступно только через VPN/прокси. Если не хочется держать включённым VPN на всю машину, можно направить через прокси только обращения бота к Telegram (остальной портал, включая локальный Ollama, прокси не трогает):

```
export FP_BOT_PROXY=http://host:port            # HTTP/HTTPS-прокси, например из Clash/v2rayN
export FP_BOT_PROXY=http://user:pass@host:port   # с авторизацией
export FP_BOT_PROXY=socks5://host:port           # SOCKS5 (нужен: pip3 install pysocks)
export FP_BOT_PROXY=socks5://user:pass@host:port
python3 run_bot.py
```

Адрес и порт берутся из настроек вашего VPN/прокси-клиента — там, где включаете VPN для бота, ищите раздел вида «Local Proxy» / «System Proxy» / «Inbound» (в Clash/ClashX обычно `127.0.0.1:7890`, в v2rayN/v2rayNG/Hiddify — свой порт; HideMy.name отдельно позволяет выбрать HTTP- или SOCKS5-прокси в настройках приложения — там же видны host и port). Если переменная не задана, бот ходит в Telegram как раньше — без изменений в поведении.

Если используете `launchd` для автозапуска (см. «Автозапуск» ниже) — добавьте `FP_BOT_PROXY` в `EnvironmentVariables` соответствующего `.plist`-файла, иначе при запуске через launchd переменная не подхватится.

### Привязка пользователя к боту

1. Owner заходит в раздел «Пользователи» в портале, нажимает «Получить код» рядом с нужным пользователем.
2. Передаёте этот код пользователю (например, в личном сообщении).
3. Пользователь находит вашего бота в Telegram, нажимает Start, затем отправляет:
   ```
   /link КОД
   ```
4. Готово — бот привязан к аккаунту, дальше все команды (`/my`, `/client`, `/add`) работают от имени этого пользователя с его правами.

### Команды бота

- `/my` — список своих обязательств с кнопками для быстрой смены статуса.
- `/client` — без аргумента бот присылает кнопки со всеми клиентами из базы (с постраничной навигацией); `/client название` — текстовый поиск, если знаете точное название. Ответ компактный: одно сообщение с итоговыми суммами (Факт/0‑100/Возможности) и одно сообщение с двумя моноширинными таблицами — «План 0‑100» и «Возможности» (без строк Факта, чтобы не загромождать чат). В таблице есть колонка «№ проекта» (важный идентификатор статьи, особенно если у клиента несколько похожих по названию проектов) и колонка «Об.» — количество обязательств по строке.
- `/clientobl название` — показать обязательства по строкам клиента с кнопками управления статусом (используется, когда в таблице `/client` видно, что по строке есть обязательства).
- `/add` — добавить обязательство: бот пошагово предлагает кнопки — клиента (текстовый поиск по подстроке), статью, текст обязательства, срок (кнопки «Сегодня», «+3 дня», «+7 дней», «По ДПА статьи», «Без срока» или ручной ввод) и ответственного.
- `/link КОД` — привязать аккаунт.
- `/help` — список команд.

**Любое сообщение без `/` в начале** — это вопрос тому же ИИ-чату, что и карточка «Спросить портал» на дашборде (см. «Чат с ИИ по порталу» ниже): тот же поиск по клиенту, разделу, рискам, обязательствам и номеру договора/проекта/ЕЗ, тот же ответ через Ollama (или локальный поиск, если Ollama не запущена). Работает без `/link` — как и `/client`.

Под каждым обязательством в боте — кнопки с статусами (Не начато / В работе / Выполнено / Блокировано), смена статуса происходит одним тапом. Менять статус может только тот, кто привязан к аккаунту ответственного (или Owner — для любых обязательств).

### Напоминания

Бот раз в 15 минут проверяет дедлайны всех обязательств и присылает уведомление ответственному, если обязательство просрочено или срок наступает в течение 3 дней. В течение одного дня по одному и тому же обязательству напоминание не дублируется.

### Ограничения текущей версии

Бот работает только когда запущен процесс `run_bot.py` на вашей машине — если компьютер выключен, напоминания не приходят и команды не обрабатываются. Настройте автозапуск (раздел «Автозапуск» выше) — тогда бот поднимается сам вместе с Mac и не требует открытого терминала. Привязка одного пользователя портала — к одному Telegram-аккаунту; для смены привязки сгенерируйте пользователю новый код.

## Логика ответственности

- Разделы **Докупки**, **Лицензии** — по умолчанию ответственный — руководитель продукта (Owner).
- Разделы **Проекты**, **Заказные доработки** — обязательство обязательно закрепляется за одним из руководителей команд (Зинин Юра, Денисова Мария, Чибизов Георгий, Фёдоров Роман, Эркенов Руслан). Если такого обязательства нет — строка попадает в список рисков на дашборде.
- Разделы **Сопровождение** и **TaaS** — ответственный не требуется. Эти разделы не участвуют в списке рисков и обязательств, а отображаются отдельным блоком на дашборде квартала только для отслеживания сумм по клиентам.

## Чат с ИИ по порталу («Спросить портал»)

Доступен в двух местах: карточка «Спросить портал» на дашборде и обычное сообщение без `/` в Telegram-боте (см. «Команды бота» выше) — это один и тот же чат, отвечает на основе одних и тех же данных.

Отвечает локальная модель через [Ollama](https://ollama.com) — она крутится на этом же компьютере, поэтому данные портала никуда в интернет не уходят и ключи API не нужны. Под капотом: по вопросу собирается релевантный кусок данных из базы (по упомянутым клиенту, разделу/портфелю, рискам, обязательствам, просрочкам, номеру договора/проекта — плюс сводка по рискам по умолчанию), и модель отвечает по этим данным обычным связным языком, а не таблицей.

Понимает свободные формулировки лучше, чем просто совпадение по словам (например, «как дела со Сбербанком» или «что сейчас горит»), умеет находить статью по номеру договора/проекта/ЕЗ прямо в тексте вопроса (даже без названия клиента), и различает два понятия риска: ручную отметку «Риск» (Низкий/Средний/Высокий, ставится на странице «Детализация») и автоматический список статей без оформленного обязательства на сумму ≥300 000 ₽ — это разные вещи. Если нужных данных не нашлось, чат честно скажет об этом, а не придумает цифры.

Ответ выводится моноширенным шрифтом (и на дашборде, и в Telegram) — так таблицы и колонки с цифрами не «расползаются» и легче читать построчно.

**Действия через чат.** Кроме вопросов, чат умеет выполнять те же действия, что доступны на страницах портала — для этого нужен привязанный аккаунт (на дашборде это сессия входа, в Telegram — команда `/link`):

- поставить/снять отметку риска по статье — только Owner, например: «поставь высокий риск по Сберу»;
- добавить обязательство / назначить ответственного по статье — например: «добавь обязательство по проекту 2606/23-2В-О: подписать акт, ответственный Зинин, срок 2026-07-01» (те же правила, что в форме на сайте: для разделов «Проекты»/«Заказные доработки» ответственный обязательно один из руководителей команд);
- изменить статус обязательства — например: «обязательство по Сберу про акт выполнено» (право менять статус — как и везде на портале: Owner или сам ответственный);
- изменить внутренний комментарий по статье — только Owner.

Если по описанию находится больше одной подходящей статьи ФП (обычно это значит, что у проекта несколько строк — по месяцам и/или портфелям Факт/0-100/Возможности), чат не угадывает, а показывает список совпадений и просит уточнить (добавить номер договора/проекта, месяц или раздел). Статью можно искать и по номеру проекта/договора без разделителей (просто «3856399») — чат сам сравнивает с тем, как номер хранится в базе. Распознавание действия — отдельный короткий запрос к той же модели в Ollama перед обычным ответом; если он не дал уверенного результата или Ollama недоступна, сообщение просто обрабатывается как обычный вопрос.

Действие выполняется не сразу: чат сначала проверяет права и параметры и пишет, что именно собирается сделать («Готов выполнить: ...»), и ждёт подтверждения следующим сообщением — «да» выполняет, «нет» отменяет, ничего другого в БД не меняется. Если вместо «да»/«нет» пришло что-то другое, предложение просто снимается, и сообщение обрабатывается как новое (вопрос или другое действие).

**Настройка (один раз):**

1. Установите [Ollama](https://ollama.com/download) и скачайте модель, например: `ollama pull qwen3:8b` (~5 ГБ, хороший баланс качества и скорости на 16 ГБ ОЗУ).
2. Убедитесь, что Ollama запущена (по умолчанию слушает `http://localhost:11434` — обычно поднимается автоматически после установки).
3. Перезапустите портал — чат начнёт обращаться к модели автоматически, никаких дополнительных пакетов ставить не нужно.

Если нужна другая модель/тег или Ollama развёрнута не на стандартном адресе/порте, задайте перед запуском переменные окружения:

- `OLLAMA_MODEL` — имя модели, **должно точно совпадать с тегом, который вы скачали** (по умолчанию `qwen3:8b`; если скачали другой тег/модель — например, более лёгкую `gemma3:4b` или `qwen3.5:4b` для слабого компьютера — укажите его здесь);
- `OLLAMA_HOST` — адрес Ollama (по умолчанию `http://localhost:11434`);
- `OLLAMA_TIMEOUT` — таймаут ожидания ответа модели в секундах (по умолчанию `60`).

У моделей с режимом «размышлений» (Qwen3.x и похожие) этот режим по умолчанию включён и сильно замедляет ответ — портал явно отключает его в запросе к Ollama (`think: false`), чтобы ответы оставались быстрыми; модели без такого режима этот параметр просто игнорируют.

**Если Ollama не запущена или модель не скачана** — чат не падает, а автоматически откатывается на старый локальный поиск по ключевым словам (без ИИ) и явно предупреждает об этом в начале ответа.

**Голосовые сообщения.** Вопрос или действие можно не печатать, а наговорить — на дашборде кнопка микрофона рядом с полем вопроса, в Telegram-боте — обычное голосовое сообщение. Распознавание речи тоже работает локально (faster-whisper, модель Whisper, без интернета и без ключей API): голос превращается в текст, чат/бот сначала показывает, что распознал, и дальше обрабатывает это ровно как печатный вопрос — включая подтверждение «да»/«нет» перед записью в БД. Отвечает чат в любом случае текстом (голосовых ответов нет).

*Настройка (один раз):*

1. Пакет `faster-whisper` уже в `requirements.txt` — поставится при обычной установке зависимостей (см. «Установка» ниже).
2. Саму модель (~500 МБ для размера `small`) faster-whisper скачивает автоматически при первом голосовом сообщении — нужен интернет один раз, дальше всё работает локально.
3. Перезапустите портал и бота.

Размер модели и устройство можно поменять переменными окружения: `FP_WHISPER_MODEL` (по умолчанию `small`; `base` — быстрее и грубее, `medium` — точнее, но медленнее на слабом компьютере), `FP_WHISPER_DEVICE` (по умолчанию `cpu`), `FP_WHISPER_COMPUTE_TYPE` (по умолчанию `int8`).

Важно для дашборда: запись голоса в браузере работает только на `https://` или на `http://localhost` — это ограничение самого браузера. Если портал открывают по обычному `http://` с другого устройства в локальной сети (не с самого компьютера, на котором он запущен), кнопка микрофона не получит доступ к микрофону; в Telegram-боте такого ограничения нет.

## Установка (один раз)

Нужен установленный Python 3.10+. Проверить: `python3 --version`.

1. Распакуйте архив в любую папку, например `C:\fp-portal` или `~/fp-portal`.
2. Откройте терминал (Командная строка / PowerShell / Terminal) в этой папке.
3. Установите зависимости:

```
pip install -r requirements.txt
```

Если `pip` не находится, попробуйте `pip3` или `python3 -m pip install -r requirements.txt`.

## Запуск

```
python3 run.py
```

(на Windows может быть просто `python run.py`)

В терминале появится:
```
ФП-Контроль запущен: http://127.0.0.1:5000
```

Откройте этот адрес в браузере. Чтобы остановить сервер — `Ctrl+C` в терминале.

При первом запуске автоматически создаётся база данных `app/data/fp_portal.db` и тестовые пользователи (см. ниже). База — обычный файл SQLite, переносится вместе с папкой проекта; можно делать бэкап, просто скопировав этот файл.

## Автозапуск (macOS): без открытого терминала

В папке `launchd/` — готовые конфиги для запуска портала и Telegram-бота через `launchd` (штатный способ автозапуска фоновых процессов на macOS): оба стартуют сами при включении/перезагрузке Mac и сами перезапускаются, если упадут. Открытое окно терминала после этого не нужно.

Установка (один раз, в Terminal, из папки проекта):

```
cp launchd/com.fpportal.web.plist launchd/com.fpportal.bot.plist ~/Library/LaunchAgents/
launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/com.fpportal.web.plist
launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/com.fpportal.bot.plist
```

Перезапустить после обновления кода (или если процесс «подвис»):

```
launchctl kickstart -k gui/$(id -u)/com.fpportal.web
launchctl kickstart -k gui/$(id -u)/com.fpportal.bot
```

Полностью выгрузить (например, перед переустановкой):

```
launchctl bootout gui/$(id -u)/com.fpportal.web
launchctl bootout gui/$(id -u)/com.fpportal.bot
```

Логи обоих процессов — в папке `logs/` (`web.out.log`/`web.err.log`, `bot.out.log`/`bot.err.log`); туда же попадают и ошибки запуска.

**Если папка проекта лежит в `Документы` с включённым iCloud Drive** — сразу после загрузки Mac система иногда на несколько секунд блокирует доступ к файлам, пока iCloud «досинхронизируется»; в логах это выглядит как `Operation not permitted` при попытке открыть `run.py`/`run_bot.py`. `KeepAlive` в конфиге сам повторяет попытки запуска, так что процесс поднимается через несколько секунд–минут без вмешательства. Чтобы убрать эту задержку совсем — перенесите папку проекта за пределы iCloud Drive (например, в `~/fp-portal`) либо отключите для неё «Оптимизация хранилища Mac» в настройках iCloud, чтобы файлы не выгружались с локального диска.

Бот может оставаться без ответа на отдельные сообщения, если на короткое время недоступен сам Telegram (сетевой таймаут) — это видно в `bot.out.log` как `Сетевая ошибка при обращении к Telegram`; бот не падает и не требует перезапуска, он просто повторяет попытку при следующем цикле опроса.

## Загрузка Excel-подложки

Заходите как Owner → «Загрузка Excel» → выбираете файл `.xlsx`. Структура колонок должна совпадать с исходным файлом:

```
Месяц | ПЦ | Раздел ФП | Наименование клиента | Номер проекта | Наименование проекта |
Менеджер проекта | Номер договора | Номер ЭЗ | СДЗ | ДПА | фДЗ | Способ учета |
0-100 от МП | Комментарий МП к СДЗ | Сумма из СRM, руб. | Сумма по 0-100, руб. |
Примечание | Портфель | Колодец
```

Если заголовки не совпадают, портал предупредит об этом после загрузки, но всё равно попытается импортировать по позициям колонок — проверьте результат на странице «Детализация».

**Как работает повторная загрузка:** каждая строка идентифицируется по сочетанию месяц + клиент + проект + раздел + договор + № ЭЗ + портфель + способ учёта (+ порядковый номер повторения, если в файле встречаются полностью одинаковые строки). Если такая строка уже есть в базе — её данные обновляются (включая сумму — изменение суммы фиксируется как изменение существующей строки, а не новая запись), а все привязанные обязательства остаются на месте. После каждой загрузки на странице сразу показывается сводка: что добавилось, что изменилось (с указанием старого и нового значения), что пропало. Новые строки добавляются. Строки, которые пропали из нового файла, не удаляются, а помечаются неактивными (чтобы не потерять историю обязательств) и не показываются в текущих списках.

## Частые вопросы

**Можно ли открыть портал с другого компьютера в офисе?**
Да, если все в одной сети. Запустите `app.run(host="0.0.0.0", port=5000)` в `run.py` вместо `127.0.0.1`, и заходите по IP-адресу машины, на которой запущен портал (например `http://192.168.1.50:5000`). Учтите, что в таком режиме данные доступны всем в сети, кто знает адрес и пароль.

**Как сделать резервную копию данных?**
Скопируйте файл `app/data/fp_portal.db` в надёжное место. Это вся база — пользователи, строки ФП, обязательства, история.

**Забыли пароль Owner?**
Удалите файл `app/data/fp_portal.db` (это сбросит вообще все данные — обязательства, строки, пользователей), либо отредактируйте таблицу `users` напрямую через любой SQLite-браузер (например DB Browser for SQLite).

**Ошибка `AttributeError: module 'hashlib' has no attribute 'scrypt'` при входе**
Встречается на некоторых сборках Python (часто системный Python 3.9 на macOS), собранных без поддержки scrypt. Портал уже настроен использовать метод хэширования `pbkdf2:sha256`, который работает везде, поэтому если вы используете архив в исходном виде — этой ошибки быть не должно. Если она всё же появилась (например, после ручного создания пользователя в обход портала), обновите Flask/Werkzeug (`python3 -m pip install --upgrade flask werkzeug --break-system-packages`) или просто пересоздайте пользователя через раздел «Пользователи» в портале.
